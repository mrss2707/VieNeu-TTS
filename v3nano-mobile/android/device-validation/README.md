# device-validation (Android)

Validation harness for `docs/_supermeo/_summary/002-v3-nano-mobile-validation.md` — proves
the four v3 Nano core ONNX graphs (`text_encoder`, `duration_predictor`, `vector_estimator`,
`codec_decoder`) load and run real inference (16-step Euler flow + CFG=3.0 + codec decode)
through `onnxruntime-android` on ARM64, across CPU/XNNPACK/NNAPI, on the full
`v3nano-mobile/eval/corpus/{smoke,stress}.jsonl` corpus. Not the mobile SDK.

Latest run (2026-09-28, multi-provider, full corpus): `v3nano-mobile/eval/reports/2026-09-28-android-emulator-arm64-multi-provider.json`,
evidence in `evidence/`. Earlier single-case run: `2026-09-28-android-emulator-arm64-fp32.json`.

## Regenerate the assets (not committed — see .gitignore)

```bash
# from the repo root, with `uv sync --group dev` already run

# 1. ONNX graphs
uv run --no-sync python - <<'EOF'
from huggingface_hub import hf_hub_download
for fn in ["text_encoder.onnx","duration_predictor.onnx","vector_estimator.onnx","codec_decoder.onnx"]:
    d = hf_hub_download("pnnbao-ump/VieNeu-TTS-v3-Nano", fn, repo_type="model")
    import shutil
    shutil.copy(d, f"v3nano-mobile/android/device-validation/app/src/main/assets/nano_graphs/{fn}")
EOF

# 2. Corpus input tensors (ids/spk/style for all smoke+stress cases) — shared with the iOS
#    harness, generated by v3nano-mobile/host/export_corpus_tensors.py. Each case now exports
#    chunks_meta.json + one chunk<k>/{ids.bin,meta.json} per chunk (sentences over
#    max_chars=140 — s07, st17 in this corpus — split into multiple chunks, same as
#    V3NanoVieNeuTTS.infer() does; NanoBenchmarkCore.runInferenceMultiChunk() joins them
#    back with edgeSilence/pausePadSamples/joinAudioChunks, ported from
#    src/vieneu_utils/core_utils.py — see docs/_supermeo/_summary/001-v3-nano-mobile.md §0.8).
uv run --no-sync python v3nano-mobile/host/export_corpus_tensors.py
rm -rf v3nano-mobile/android/device-validation/app/src/main/assets/nano_test_input/corpus/cases
cp -R v3nano-mobile/host/_exported_corpus_tensors/* v3nano-mobile/android/device-validation/app/src/main/assets/nano_test_input/corpus/
```

## Build & run — two paths depending on target

The benchmark logic (`Graphs`, `sessionOptionsForProvider`, `runInference`, the
corpus/provider loop) lives in `NanoBenchmarkCore.kt` (main source set), shared by both
paths below — same behavior, same `RESULT_JSON_CHUNK_N` output format via
`adb logcat -s NanoEngineTest:I` (results are chunked — logcat truncates long lines).

### Emulator / CI: `androidTest` (instrumented test)

```bash
export ANDROID_HOME=/opt/homebrew/share/android-commandlinetools   # or your SDK path
export JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk-17.jdk/Contents/Home
gradle connectedDebugAndroidTest --console=plain
```

Requires a running device/emulator (`adb devices`). The emulator setup used for the
2026-09-28 report: `system-images;android-34;google_apis;arm64-v8a` AVD, booted headless
(`-no-window -no-audio -no-boot-anim`), accelerated via Hypervisor.framework.

**Do NOT use this path on a real OnePlus/Oppo (ColorOS/OxygenOS) device** — see next
section.

### Real device: `MainActivity` (foreground app)

On a real OnePlus PHP110 (OxygenOS), `connectedDebugAndroidTest` was repeatedly frozen
mid-benchmark by the OS's `OplusHansManager` ("Hans" StrictMode heuristic — it treats a
process sustaining >300% CPU as abnormal and freezes it, even after whitelisting it in
`dumpsys deviceidle` and disabling `cached_apps_freezer`), because an instrumentation
process with no UI is still classified as background regardless of those settings. Fix:
run the benchmark inside a **foreground Activity with a visible window** instead — this
gets a different (foreground) process priority class (`nice=-10` observed vs. `nice=20`
for the instrumented test) that OEM background-freezers do not target the same way.

```bash
export ANDROID_HOME=/opt/homebrew/share/android-commandlinetools
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb logcat -c
adb shell am start -n com.vieneu.mobile.validation/.MainActivity
adb logcat -s NanoEngineTest:I   # watch progress; app auto-runs the full corpus on launch
```

The app shows live progress on-screen (`FLAG_KEEP_SCREEN_ON` set) and also writes the
final JSON to `getExternalFilesDir(null)/nano_android_result_real_device.json` as a
backup in case logcat truncates. Takes ~10-11 minutes total on a flagship-tier device (3
providers x ~40 cases each; NNAPI is markedly slower than CPU/XNNPACK).

Result for the 2026-09-28 real-device run (OnePlus PHP110, MediaTek mt6983):
`v3nano-mobile/eval/reports/2026-09-28-android-real-device-multi-provider.json` — **RTF
median on CPU (0.61) exceeds the ≤0.5 target from plan 001 §2.2**, on a flagship SoC.

Known pitfall: `createSession(byte[])` OOMs the Dalvik heap on `vector_estimator.onnx`
(155MB) — the code copies assets to a cache file and uses `createSession(path)` instead.
